# Deployment

Two supported targets: Vercel (`vercel.ts`) and a container (`Dockerfile`).
Both run the same build; the difference is who terminates TLS and who owns
the wildcard certificate.

Everything below assumes `DATA_MODE=db`. Fixture mode needs no
infrastructure at all — no database, no secrets, no migrations — which is
why it is the mode a demo runs in.

---

## 1. Blockers in `0001_init` — read before you run a migration

`prisma/migrations/0001_init/migration.sql` does not apply to a clean
Postgres 15 as written. Three problems, all of which have to be fixed by
editing that file in place. Editing an applied migration is normally
forbidden; it is safe here **only** because it has never run against a
production database. Once it has, these become follow-up migrations.

**a. The `citext` extension is never created.** `member_contacts.email`,
`member_contacts.alt_email` and `tenant_branding.support_email` are `citext`
columns. The migration creates `pgcrypto` and `pg_trgm` and stops there, so
it dies at `CREATE TABLE member_contacts` with `type "citext" does not
exist`. Add it alongside the others:

```sql
CREATE EXTENSION IF NOT EXISTS "citext";
```

**b. `chk_reconciler_not_creator` uses a subquery.** Postgres does not allow
subqueries in `CHECK` constraints, and `NOT VALID` does not exempt it — it
is rejected at parse time with `cannot use subquery in check constraint`.
The rule it encodes is real (a campaign's creator must not be its sole
reconciler) but it is a trigger or an application-level check, not a
constraint. Delete the `ALTER TABLE donations ADD CONSTRAINT` block and
enforce it in the donations module.

**c. The RLS policies use the one-argument `current_setting`.**

```sql
USING (tenant_id = current_setting('app.tenant_id')::uuid)
```

When `app.tenant_id` has never been set on the connection, this **raises**
`unrecognized configuration parameter` rather than returning no rows. Both
`ARCHITECTURE.md` and `src/lib/db/client.ts` describe the intended
behaviour as "policies evaluate false and queries return nothing", which
needs the two-argument form:

```sql
USING (tenant_id = current_setting('app.tenant_id', true)::uuid)
```

With `missing_ok` the setting comes back `NULL`, the comparison is `NULL`,
the policy is false, and a missing tenant context yields an empty result —
the failure mode the design actually wants.

### And one that is not a syntax error

The migration runs `ENABLE ROW LEVEL SECURITY` but not `FORCE ROW LEVEL
SECURITY`. **A table's owner bypasses RLS.** If the application connects
with the same role that ran the migration — the default on a managed
Postgres where you get one user — then tenant isolation, the load-bearing
decision this whole schema is built around, is switched off and nothing
anywhere will tell you.

Pick one:

- **Two roles (preferred).** `alumni_migrate` owns the schema and runs
  migrations; `alumni_app` is granted DML only and is the role in
  `DATABASE_URL`. RLS applies to it because it owns nothing.
- **Force it.** `ALTER TABLE <t> FORCE ROW LEVEL SECURITY` for all 18
  tables. Note this also applies the policies to the migration role, so
  future data migrations have to set `app.tenant_id` themselves.

Verify after deploying, connected as the application role:

```sql
SELECT count(*) FROM members;   -- expect: ERROR, or 0 rows. Never a number.
```

## 2. Migrations

```bash
npx prisma migrate deploy
```

`migrate deploy` and nothing else, in every environment above a laptop.

> **`prisma migrate dev` must never regenerate `0001_init`.**
>
> The SQL file is the source of truth. It holds every row-level security
> policy, the `name_normalised` generated column, the trigram indexes and
> `rollover_batch()` — and Prisma's schema language can express none of
> them. A regenerated initial migration is a schema that looks identical in
> `schema.prisma`, applies without an error, and has no tenant isolation.
> Nothing in the test suite fails. You find out when one college can read
> another's directory.
>
> When the schema changes: write the SQL migration by hand, then mirror the
> shape into `schema.prisma`. Same rule as the comment at the top of that
> file.

`prisma migrate deploy` also needs a lock file that is not in the repo:

```toml
# prisma/migrations/migration_lock.toml
# Please do not edit this file manually
provider = "postgresql"
```

Without it the deploy aborts before it applies anything.

Expect `prisma migrate status` and `prisma db pull` to report drift
against `schema.prisma` — the generated column and the RLS policies have
no Prisma representation. That drift is expected and is not a signal to
run `migrate dev`.

## 3. Environment

`.env.example` is the full list, annotated with which variables are
required in production and which have safe fallbacks. The short version:

| Variable | |
|---|---|
| `DATABASE_URL` | Required. ap-south-1 Postgres 15+. Non-owner role — see §1. |
| `SESSION_SECRET` | Required. `openssl rand -base64 32`. The app refuses to boot without it outside fixture mode, and rotating it signs everyone out. |
| `DEFAULT_TENANT_SUBDOMAIN` | Falls back to `diet`. Only used for hosts with no usable subdomain. |
| `RESEND_API_KEY` / SES credentials | Required — email OTP is the primary credential. |
| `EMAIL_BOUNCE_WEBHOOK_SECRET` | Required. An imported alumni list is full of dead college addresses; unhandled bounces burn the sending domain in week one. |
| `S3_*` | Required for uploads. `ap-south-1`. |
| `REDIS_URL` | Required as soon as there is more than one instance — the OTP store in `session.ts` is in-process. |
| `RAZORPAY_*` | Leave empty until the college confirms FCRA registration. |
| `PRIVACY_NOTICE_VERSION` | Bump whenever the notice text changes. |

Everything with personal data in it stays in `ap-south-1`. That is not a
latency preference — keeping storage and compute inside India is what keeps
DPDP cross-border transfer out of scope.

## 4. Vercel

`vercel.ts` sets the framework, the region and the static cache headers.

**`@vercel/config` is not installed.** The file imports it anyway, with a
`@ts-ignore`, so that installing the package is the only step needed to
make it typed and live. Until then Vercel uses the project's dashboard
settings and this file has no effect — so anything in it that matters
(the region, in particular) must also be set in the dashboard. To adopt it:

```bash
npm install --save-dev @vercel/config
```

Then remove the `@ts-ignore` and confirm the exported symbol is
`defineConfig`; if the package's API differs, the type error will say so.
`vercel.json` remains the alternative if the typed config is not wanted.

### Region

`bom1`. Functions must sit next to the database — a Mumbai database served
from `iad1` is both a 200ms round trip per query and an export of personal
data out of India. Multi-region is a paid feature; on a single-region plan,
`bom1` is the one region to select.

Edge middleware is the exception and runs everywhere by design. That is
acceptable because `src/middleware.ts` reads the `Host` header and nothing
else — no database, no session, no member data. Keep it that way.

### Environment variables

Set them for **Production and Preview separately**. Preview deployments
resolve to `*.vercel.app`, which has no usable subdomain, so they fall back
to `DEFAULT_TENANT_SUBDOMAIN`. A preview pointed at the production
`DATABASE_URL` is a live college's data behind a URL anyone with the link
can open.

## 5. Docker

```bash
docker build -t alumni-portal .
docker run -p 3000:3000 --env-file .env.production alumni-portal
```

**`next.config.ts` must set `output: 'standalone'`.** It does not today.
Without it `next build` never writes `.next/standalone` and the runner
stage fails on a missing `server.js` — which reads like a bad `COPY` path,
so check the config line first.

The image runs as an unprivileged user and contains no source, no dev
dependencies and no package manager. It therefore cannot run migrations:
`prisma migrate deploy` needs the Prisma CLI, which is a dev dependency,
and shipping it would put a schema-modifying binary inside the request-
serving container. Run migrations from CI, or from a one-off container
built from the `builder` stage:

```bash
docker build --target builder -t alumni-migrate .
docker run --rm -e DATABASE_URL="$DATABASE_URL" alumni-migrate npx prisma migrate deploy
```

There is no `HEALTHCHECK` because there is no health endpoint yet. Add
`/api/health` and point the orchestrator at it before this goes behind a
load balancer.

## 6. DNS and TLS for subdomain tenancy

One deployment serves every college, separated by subdomain:
`diet.portal.example` and `xyz.portal.example` are the same code and
different worlds. Adding a college is a DNS record, not a deploy.

That only holds if the certificate is a wildcard, which is where this gets
operational.

**On Vercel.** Add `*.portal.example` as a domain on the project. Vercel
issues a wildcard certificate only when the domain's **nameservers point at
Vercel DNS** — the ACME DNS-01 challenge needs to write a TXT record, and
it cannot do that on a domain it does not control. If the college insists
on keeping DNS with their existing provider, you are adding and verifying
each tenant hostname by hand, which quietly turns onboarding back into a
ticket. Decide this before selling the second college.

Also add the apex and `www` for the marketing site.

**Self-hosted.** Terminate TLS at nginx or Caddy with a wildcard
certificate obtained via DNS-01 (`certbot` with the provider's plugin, or
Caddy's DNS modules — HTTP-01 cannot issue wildcards). Proxy everything to
the container and pass the original host through:

```nginx
proxy_set_header Host $host;
proxy_set_header X-Forwarded-Proto $scheme;
```

Both matter. `Host` is how the tenant is resolved at all; `X-Forwarded-Proto`
is how the middleware decides whether to send HSTS.

**Development.** `*.localhost` resolves to 127.0.0.1 in Chrome and Firefox
without a hosts-file entry, so `http://diet.localhost:3000` and
`http://demo.localhost:3000` work directly. Plain `localhost`, `127.0.0.1`
and `*.vercel.app` fall back to `DEFAULT_TENANT_SUBDOMAIN`. That fallback
does not apply on a real production host: an unrecognised host there is a
misconfigured DNS record or someone probing, and both 404.

## 7. The CSP contract with the root layout

`src/middleware.ts` sets a Content-Security-Policy with a per-request nonce
and exposes it as the `x-nonce` request header. Two things in the root
layout depend on getting this right.

**The inline theme `<script>` must carry the nonce.** Next.js stamps its
own bootstrap scripts automatically — it parses the nonce back out of the
CSP header set on the request — but a hand-written inline script is on its
own, and a blocked one fails silently apart from a theme flash on every
navigation.

```tsx
const nonce = (await headers()).get('x-nonce') ?? undefined;
<script nonce={nonce} dangerouslySetInnerHTML={{ __html: THEME_BOOT }} />
```

**The inline `<style id="tenant-brand">` must *not*.** `style-src` keeps
`'unsafe-inline'`, because a nonce cannot be attached to a style
*attribute* and inline `style={{ ... }}` props are how token values reach
the DOM in the chart components. Adding a nonce to `style-src` would make
CSP3 ignore `'unsafe-inline'` — the brand block would keep working while
every computed bar width in the app stopped rendering. Half-noncing styles
is the failure mode; the full reasoning is in the middleware.

`fonts.googleapis.com` and `fonts.gstatic.com` are allowed because font
choice is tenant configuration resolved at runtime. `next/font` resolves at
build time and cannot serve a typeface a college picks after deploy.

After any change to the layout or the CSP, load a page and check the
console for `Refused to …`. There is no test for this.

## 8. Seeding

`prisma/seed.ts` loads the fixture dataset — the same 310 members, 792
degree-register rows, events, jobs and campaigns the demo runs on — into
Postgres.

```bash
DATABASE_URL="postgresql://…" npx tsx prisma/seed.ts
```

Idempotent: every primary key is a UUIDv5 derived from the row's natural
key, so re-running updates rows rather than duplicating them. It refuses to
run with `NODE_ENV=production` unless `ALLOW_PRODUCTION_SEED=yes`, because
demo alumni in a real college's directory is not a mistake anyone gets to
fix quietly.

It does **not** seed `audit_log`, `consent_records` or `data_requests`.
Those are records of things that happened; fabricating them produces an
audit trail of actions nobody took and a DPDP clock counting down on a
request nobody made.

To wire it into `prisma db seed`, add to `package.json`:

```json
"prisma": { "seed": "tsx prisma/seed.ts" }
```

A real college's instance is seeded from their degree register instead —
that loader is not built yet, and it is the longest-lead-time dependency on
the project.

## 9. Go-live checklist

**Database**

- [ ] Postgres 15+ in `ap-south-1`, automated backups on, PITR configured.
- [ ] The three `0001_init` fixes from §1 are applied.
- [ ] `migration_lock.toml` exists.
- [ ] `prisma migrate deploy` has run and `migrate status` is clean.
- [ ] `DATABASE_URL` uses a role that does **not** own the tables, or every
      table has `FORCE ROW LEVEL SECURITY`.
- [ ] Verified by hand: a `SELECT` from `members` as the app role, with no
      `app.tenant_id` set, returns nothing.
- [ ] Two tenant rows exist and neither can see the other's members.

**Secrets and services**

- [ ] `SESSION_SECRET` generated fresh for this environment, in the secret
      store rather than a `.env` file in the image.
- [ ] Email provider verified for the sending domain, with SPF, DKIM and
      DMARC published.
- [ ] Bounce and complaint webhooks are receiving events. Send one to a
      known-dead address and confirm it lands.
- [ ] S3 bucket in `ap-south-1`, public access blocked, CORS limited to the
      portal's origins.
- [ ] Redis reachable, and OTP issue/verify tested across two instances.
- [ ] Razorpay keys **absent** unless the college has confirmed FCRA
      registration.

**Routing**

- [ ] Wildcard DNS record in place and the wildcard certificate issued
      (§6) — not just the first tenant's hostname.
- [ ] `Host` and `X-Forwarded-Proto` survive the proxy.
- [ ] An unknown subdomain 404s rather than serving the default tenant.
- [ ] HSTS present on an https response, absent on http.

**Application**

- [ ] `output: 'standalone'` set if deploying the container.
- [ ] Browser console clean of CSP violations on sign-in, the directory and
      one admin page.
- [ ] The theme does not flash on navigation — the nonce reached the inline
      script.
- [ ] Fonts load from `fonts.gstatic.com` (or self-hosted, per the pack).
- [ ] Sign in as each of the nine demo roles and confirm the navigation and
      the guards agree.
- [ ] A student account cannot reach an alumnus's contact details by any
      route, including the API.
- [ ] Bulk export is refused for every role except `college_admin`, and the
      successful one writes an `audit_log` row with actor, scope and reason.
- [ ] The donations module is invisible to students and to everyone else
      until `features.donations` is on.

**Legal and operational**

- [ ] Privacy notice published and `PRIVACY_NOTICE_VERSION` matches it.
- [ ] DPDP export and deletion endpoints exist and have been exercised —
      the 30-day clock in `data_requests` starts whether or not anyone is
      watching it.
- [ ] Someone at the college owns the alumni cell account, and knows they
      do.
